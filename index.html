02 — Systems built & shipped

Things running in production, mostly somewhere without Wi-Fi.

Buzz AI

Live · Indian Navy, DRDO

On-premise agentic AI platform

Open-source LLMs (Llama 3, Mistral) behind a RAG pipeline on PostgreSQL and pgvector, with multi-step agentic workflows, tool calling and fallback logic, evaluation frameworks and guardrails. Around 100 concurrent users ask questions of their own documents and every answer is cited to its source. Fully air-gapped: no data leaves the site.

The hard part was never the LLM. It was ingestion, chunking, metadata filtering and reranking, iterated until retrieval returned the right context for each kind of question.

03 — How I work

A few habits that came from deploying where nobody can help you.

  1. Sit with the work first

    I go on-site and watch before I build. At Optiply and at MDL, the real workflow was different from the documented one almost every time.

  2. Test value before building

    Given an open brief from a utility, I mapped their operations into 15 AI use cases, ranked them by value and ease, and anchored the roadmap on the strongest one.

  3. Make the tenth deploy boring

    Automate it, runbook it, and make rollback one command. If every install is heroic, the system isn’t done.

  4. Write it down

    Integration guides, API specs, runbooks, prompt evaluation playbooks. Each one is written so the next person can use it without getting me on a call.

  5. Own it in the field

    I’ve debugged production at 2am inside air-gapped naval facilities with no internet and no one to escalate to. You make the call, then you fix it.
