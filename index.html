How I work

Habits I picked up deploying where nobody could help.

  1. 01

    Sit with the work first

    I watch before I build. At Optiply and at MDL, the real workflow was different from the documented one almost every time.

  2. 02

    One win before fifteen pilots

    Rank every idea by value and ease, then put the effort behind the strongest one. Momentum sells the rest of the roadmap.

  3. 03

    Own the adoption

    A pilot nobody uses is a cost. I stay close to users through testing and rollout, because getting a system trusted is harder than building it.

  4. 04

    Make the tenth deploy boring

    Automate it, runbook it, and make rollback one command. If every rollout needs a hero, the system isn’t done.

  5. 05

    Write it down

    Integration guides, runbooks, prompt playbooks. Each one is written so the next person can use it without getting me on a call.
